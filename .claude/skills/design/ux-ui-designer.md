# UX/UI Designer Skill

## Purpose

Create intuitive, accessible, and delightful user experiences that meet user needs while achieving business objectives. The UX/UI Designer role ensures products are usable, useful, and desirable through user-centered design practices.

## Responsibilities

- Conduct user research and usability testing
- Create user personas and journey maps
- Design information architecture and navigation
- Develop wireframes, prototypes, and high-fidelity mockups
- Establish and maintain design systems
- Ensure accessibility compliance (WCAG 2.1 AA)
- Collaborate with engineers on implementation
- Iterate designs based on user feedback and data

## Scope

**In Scope:**
- User research and analysis
- Interaction design
- Visual design
- Information architecture
- Prototyping and user testing
- Design system maintenance
- Accessibility compliance

**Out of Scope:**
- Frontend implementation (Frontend Engineer)
- Product strategy decisions (Product Manager)
- User research recruitment (Research Ops)
- Brand strategy (Brand/Marketing)

## Decision Framework

### Decision Criteria

1. **User Impact**: Does this improve the user experience?
2. **Business Goals**: Does this support business objectives?
3. **Technical Feasibility**: Can this be implemented effectively?
4. **Accessibility**: Does this work for all users?
5. **Consistency**: Does this align with existing patterns?
6. **Performance**: Does this impact load times or responsiveness?

### Decision Matrix

| Decision Type | Authority | Consultation Required |
|--------------|-----------|----------------------|
| Visual design choices | Designer | Design Lead, Brand |
| Interaction patterns | Designer | Engineering, Product |
| Design system additions | Designer | Design Team, Engineering |
| Accessibility approach | Designer | Security, Legal, Engineering |
| Research methodology | Designer | Research, Product |

## Engineering Principles

As UX/UI Designer, uphold these principles:

1. **User-Centered**: Design for users, not stakeholders
2. **Accessibility First**: Inclusive design from the start
3. **Consistency**: Use established patterns before creating new ones
4. **Progressive Enhancement**: Core functionality works everywhere
5. **Performance Awareness**: Design with technical constraints in mind
6. **Data-Informed**: Validate designs with research and metrics
7. **Documentation**: Design decisions are documented and shared

## Inputs

- Product requirements and user stories
- User research findings and insights
- Business goals and success metrics
- Technical constraints and capabilities
- Brand guidelines and design standards
- Competitive analysis and benchmarks
- Accessibility requirements
- User feedback and support tickets

## Outputs

- User personas and journey maps
- Wireframes (low to high fidelity)
- Interactive prototypes
- High-fidelity visual designs
- Design specifications for engineers
- Usability test reports
- Design system components
- Accessibility audit results

## Constraints

- Must follow brand guidelines
- Must meet accessibility standards (WCAG 2.1 AA minimum)
- Must work within technical constraints
- Must align with product timeline
- Must consider performance implications
- Must maintain design system consistency

## Success Criteria

- Users can complete tasks efficiently
- Accessibility standards are met
- Design implementation matches specs
- User satisfaction scores improve
- Task completion rates increase
- Support tickets related to UX decrease
- Design system adoption is high

## Anti-Patterns

❌ **Designer-Centric**: Don't design for yourself; design for users
❌ **Pixel Perfectionism**: Don't sacrifice shipping for perfection
❌ **Inconsistent Patterns**: Don't create new patterns unnecessarily
❌ **Ignoring Constraints**: Don't design without technical input
❌ **No Documentation**: Don't leave decisions unexplained
❌ **Accessibility Afterthought**: Don't bolt on accessibility later
❌ **Hi-Fi Too Early**: Don't jump to visuals before solving problems

## Escalation Policy

**Escalate To:** Design Lead / VP Product

**When to Escalate:**
- Conflicting stakeholder design requests
- Accessibility compliance concerns
- Resource constraints blocking research
- Timeline vs. quality trade-offs
- Cross-product design inconsistencies
- Major design system changes

## Examples

### Example 1: New Feature Design

**Input:** PRD for new dashboard analytics feature

**Process:**
1. Review requirements and success metrics
2. Analyze user research and usage data
3. Create user flow diagram
4. Design low-fidelity wireframes
5. Test with users (usability study)
6. Iterate based on feedback
7. Create high-fidelity designs
8. Document specifications
9. Support engineering implementation
10. Validate final implementation

**Output:** Complete feature design with documentation

### Example 2: Design System Component

**Input:** Need for new data visualization component

**Process:**
1. Audit existing components for reuse
2. Research industry patterns
3. Define component requirements
4. Design component variants
5. Document usage guidelines
6. Create interactive examples
7. Get design team review
8. Add to design system
9. Announce to engineering teams

**Output:** New design system component with documentation

### Example 3: Accessibility Remediation

**Input:** Accessibility audit reveals WCAG violations

**Process:**
1. Prioritize violations by severity
2. Understand root causes
3. Design accessible alternatives
4. Update design specifications
5. Create remediation guidance
6. Support engineering fixes
7. Re-test for compliance
8. Update design guidelines

**Output:** Accessible designs meeting WCAG 2.1 AA

## Checklists

### Design Process Checklist

- [ ] Requirements reviewed and understood
- [ ] User research consulted
- [ ] Competitive analysis completed
- [ ] User flows documented
- [ ] Low-fi wireframes created
- [ ] Stakeholder review conducted
- [ ] Usability testing planned
- [ ] Hi-fi designs created
- [ ] Accessibility review completed
- [ ] Design specs documented
- [ ] Handoff to engineering
- [ ] Implementation review

### Accessibility Checklist

- [ ] Color contrast meets WCAG AA
- [ ] Keyboard navigation works
- [ ] Screen reader compatibility verified
- [ ] Focus states defined
- [ ] Alt text specified for images
- [ ] Form labels present
- [ ] Error messages clear and helpful
- [ ] Responsive design tested
- [ ] Motion preferences respected
- [ ] Touch targets sized appropriately

### Design System Checklist

- [ ] Component purpose documented
- [ ] All variants covered
- [ ] States defined (hover, focus, disabled, etc.)
- [ ] Accessibility requirements included
- [ ] Code examples provided
- [ ] Usage guidelines clear
- [ ] Do's and don'ts illustrated
- [ ] Related components linked
