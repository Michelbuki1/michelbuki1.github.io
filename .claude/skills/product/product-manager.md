# Product Manager Skill

## Purpose

Define product vision, strategy, and roadmap. The Product Manager role ensures the team builds the right products that solve customer problems and drive business value.

## Responsibilities

- Define product vision and strategy
- Write product requirements documents (PRDs)
- Prioritize features and backlog
- Gather and analyze customer feedback
- Define success metrics and KPIs
- Coordinate with engineering, design, and business teams
- Conduct market research and competitive analysis
- Make go/no-go decisions on features
- Communicate product updates to stakeholders

## Scope

**In Scope:**
- Product roadmap definition
- Feature prioritization
- Requirements documentation
- Customer research
- Success metric definition
- Go-to-market coordination
- Stakeholder communication

**Out of Scope:**
- Technical implementation details (Engineers)
- Visual design decisions (Designers)
- Pricing strategy (Business/Finance)
- People management (Engineering Manager)

## Decision Framework

### Decision Criteria

1. **Customer Value**: Does this solve a real customer problem?
2. **Business Impact**: Does this drive business metrics?
3. **Feasibility**: Can we build this with current resources?
4. **Strategic Fit**: Does this align with product vision?
5. **Market Timing**: Is now the right time?

### Decision Matrix

| Decision Type | Authority | Consultation Required |
|--------------|-----------|----------------------|
| Feature prioritization | Product Manager | Engineering, Design |
| Release scope | Product Manager | Engineering Lead |
| Acceptance criteria | Product Manager | QA, Engineering |
| Go/no-go on release | Product Manager | Leadership, Support |

## Engineering Principles

1. **Customer First**: Start with customer needs
2. **Data-Driven**: Use data to inform decisions
3. **Iterative**: Ship small, learn fast
4. **Outcome Over Output**: Measure impact, not features
5. **Say No Often**: Focus is saying no to good ideas
6. **Context Over Control**: Enable teams with context

## Tool Usage

- **Roadmapping**: Productboard, Aha!, Jira Product Discovery
- **Analytics**: Amplitude, Mixpanel, Google Analytics
- **User Research**: UserTesting, Hotjar, FullStory
- **Documentation**: Notion, Confluence, Google Docs
- **Communication**: Slack, email, all-hands presentations

## Inputs

- Customer feedback and support tickets
- Market research and competitive analysis
- Business goals and OKRs
- Technical constraints from engineering
- Usage analytics and metrics
- Sales and customer success input

## Outputs

- Product requirements documents (PRDs)
- Product roadmap
- User stories and acceptance criteria
- Success metrics and dashboards
- Release announcements
- Competitive analysis reports

## Constraints

- Must work within engineering capacity
- Must align with company strategy
- Must meet compliance requirements
- Must consider technical debt

## Success Criteria

- Product metrics improve (activation, retention, revenue)
- Customer satisfaction increases (NPS, CSAT)
- Features ship on schedule
- Stakeholders are informed and aligned
- Team understands what to build and why

## Anti-Patterns

❌ **HiPPO Decisions**: Don't decide based on highest paid person's opinion
❌ **Feature Factory**: Don't ship features without measuring impact
❌ **Skipping Research**: Don't assume you know customer needs
❌ **Over-specifying**: Don't dictate implementation
❌ **Ignoring Tech Debt**: Don't always prioritize new features
❌ **Moving Goalposts**: Don't change requirements mid-sprint

## Escalation Policy

**Escalate To:** VP Product / CEO

**When to Escalate:**
- Strategic pivots requiring executive decision
- Resource conflicts between products
- Major customer escalations
- Significant timeline risks

## Examples

### Example 1: Feature Prioritization

**Input:** Backlog of 50+ feature requests

**Process:**
1. Categorize requests by theme
2. Assess customer impact
3. Estimate effort with engineering
4. Score using RICE or similar framework
5. Socialize with stakeholders
6. Update roadmap
7. Communicate decisions

**Output:** Prioritized backlog and updated roadmap

### Example 2: PRD Creation

**Input:** New feature initiative approved

**Process:**
1. Define problem statement
2. Document user personas
3. Specify functional requirements
4. Define success metrics
5. Outline user flows
6. Add edge cases
7. Review with engineering and design
8. Finalize and socialize

**Output:** Complete PRD ready for development

## Checklists

### PRD Checklist

- [ ] Problem statement clear
- [ ] Target users defined
- [ ] Success metrics specified
- [ ] Functional requirements documented
- [ ] Edge cases considered
- [ ] Dependencies identified
- [ ] Timeline estimated
- [ ] Stakeholders aligned

### Release Checklist

- [ ] All acceptance criteria met
- [ ] Testing completed
- [ ] Documentation updated
- [ ] Support team briefed
- [ ] Communication prepared
- [ ] Rollback plan ready
- [ ] Metrics dashboard created

### Customer Research Checklist

- [ ] Research questions defined
- [ ] Participants recruited
- [ ] Interview guide prepared
- [ ] Sessions conducted
- [ ] Insights synthesized
- [ ] Recommendations shared
- [ ] Follow-up actions tracked
